# Pawradise production art and interaction contract
Approved direction from player flow review, 27 November 2026. Permanent world name Pawradise; keep meowbox repository, deployment URL, existing storage keys and shared links. This is a specification, not evidence of delivered assets or live UAT.

## Production gate
Before art: identify player intent, route from entrance to station and back, physical layout, interaction states, result, cancel/reopen, repeated visit, portrait/landscape, EN/ZH and mentally simulate all actions. Identify existing satisfactory art and reuse. Inventory canonical runtime IDs; no new locations or currency merely for art. The 30-lens release audit remains required. Every batch: plan space -> mental UAT -> asset manifest -> generate only needed independent assets -> integrate -> actual browser and visual UAT -> commit. Do not install illustrated posters or concept sheets as functional pages.

## Scene and asset standard
Environment: separate clean architectural/scenic plate from interactive props; native portrait and landscape with common world coordinates/geometry, never crop away exits or stations. Same art direction and real walking boundaries. Transparent object sprites trimmed with safe margin, consistent perspective/lighting, no checkerboard baked into alpha. Use optimized WebP/PNG; retain source masters separately if available. No embedded names, labels, numbers, selected ticks, balances or results. Each item manifest: stable ID, source/derivative, dimensions, orientation, ground/hand anchor normalized to image, footprint, interaction approach, draw depth, state variants, animation timing and fallback. Separate foreground occluders and shadows. Match character feet to walkable ground and hand to held prop. Use actual alpha and visual checks, no clipped limbs. Fonts: proposed Lora/ Noto Serif SC for headings, readable Latin sans/Noto Sans SC for body; verify availability, contrast and fallback before adopting. EN or simplified ZH per setting, no duplicate bilingual signage except intentional cultural artifact. Proposed text #49382C, secondary #796451, paper #F5EBD9, selected #63775E, accent #A65B45; verify contrast. Keep interface compact, no long EDM, no redundant logos or headers. Live controls not decorative boxes. At mobile widths scene occupies primary viewport, contextual drawer; desktop contextual side panel. Reduced motion preserves usability.

## My Room (reference locked)
User supplied three miniature room screenshots on 26 Nov. Mandatory isometric cutaway dollhouse, two visible walls, open front, usable floor; Pawradise painted appearance, not pixel or 3D imitation. Do not use a static furnished room photo. Maintain consistent projection across shell, furniture and accessories. Empty shell base; floor/wall material layers clipped to surfaces, separate windows/door/curtains, outdoor view and light, floor grid/placement overlay only in edit mode. Independent ground-anchored furniture assets with supported orientations, finish masks or separate variant renders, distinct basic/everyday/premium catalogues. Include bed, sofa, chair, table, desk, wardrobe, shelves, rugs, lights, plants, cushions, curtains, accessories; inventory existing items first. Repeatable wallpaper, floor/tiles and material swatches. Expansion adds real floor/rooms and traversable connection; no fake larger photograph. Preserve existing economy and inventory. Catalogue -> item -> choose finish -> preview in actual room (no purchase yet) -> confirm once -> placement -> use. Tick and colour swatch are live UI, not art. Cancel restores prior state. Existing furniture can move/rotate/customise per supported rules. No overlapping invalid footprint or inaccessible door. Mobile collapsible drawer, desktop side panel, small product batches. Characters walk, sit, sleep; cat walks and sleeps; curtains move, sunlight changes, lamp light toggles, all independent. Store actual room state across orientation and revisit. Test insufficient funds, cancellation, duplicate tap, occupied floor, rotation, expansion, return from catalog, share snapshot.

## Tab and subpage requirements
Explore: physical travel notebook/map, visited stamp, destination detail, journey board, memories. Today: concise daily planner/tasks, optional gratitude, calendar and result. Town Hall: separate notices, news, gossip and chat without duplicated top-level navigation; note and newspaper assets, readable text and reply controls. My Room: actual room, edit mode, catalogue, filters, item details, material/colour, preview, purchase, placement, inventory, shelf/album, collection details, empty states. Profile: full original avatar, XP, settings, audio, language, accessibility. Fortune/tarot history: actual drawn slips/cards. Personality/parallel-life results: distinct actual result illustration. Cameos: individual portraits and actual encounter records. Achievements: unique stamps and badge sprites. Each subpage has one primary purpose, context-specific controls, previous parent restored on back including scroll/filter/selection; no duplicate profile or map. UI includes blank illustrated signs, selection/press/disable states, original navigation symbols, Pawr Coin, concise loading and error states. No long scrolling poster.

## Asset registry and ambient life
Produce transparent individual props for all above, including bench/stool sitting anchors, lamps, lanterns, hand-held ritual tools, cards, badges, collectibles and coin. Four original avatars preserved; eight directional views where supported, consistent height and foot/hand anchors; walk, turn, idle, blink, wave, sit, sleep, kneel/bow, grip, strike, stir, pour, drink, emotional reactions. Permanent NPCs, occasional/rare visitors and pets distinct and consistent; actual roster audit before asset count. Ambient loops local, independent phases: breeze, curtains, smoke, steam, water, foliage, candle/lamp glow, weather, animals and NPC routines. No whole background oscillation, artificial constant flicker, jitter or excessive motion. Reduced-motion fallback.
Sharing: clean blank templates for fortune, tarot, room snapshot, travel postcard, cameo, dish, badge, personality and story ending; live selected language and real data, format 9:16/4:5/square where relevant; no private information without explicit selection.

## Validation
Register asset IDs and mapping to current source before generation. Check alpha, anchor, object alignment, collision, labels, readability, state transitions, screen crops, memory/performance. Test 320/360/390/430 widths, tablet and desktop, touch/keyboard, language change and rotation, interruption, save and resume, network/art failures, repeat visits. Capture actual animation recordings and screenshots at meaningful state transitions; 100ms sampler flags runtime stalls, not proof of visual quality. Distinguish design specified / art produced / installed / runtime tested / visually accepted. No completion claim from mockups or syntax checks.
