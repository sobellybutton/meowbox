# Pawradise interaction and visual blueprint (proposed)
26 November 2026. Owner requests finer click-by-click design before implementation. This is a proposed interaction contract, not runtime changes or visual acceptance. Keep the current four districts, routes, URLs, save keys, earned items, existing good paintings, avatar identities, and Paw Coins. Pawradise is the permanent world name. Do not rename meowbox repository or deployment. BrbLife remains undecided. Read FINAL_PRODUCT_BRIEF.md and STATUS.md for existing curation and actual implementation.

## State model
First visit: station -> ticket/name -> full-body avatar -> ticket stamp -> board -> full-screen moving train -> gateway -> walk into Fortune Valley. Returning player: resume previous safe location; no compulsory registration/ticket/ride. Outdoor town -> tap doorway -> walk actual route -> enter physical threshold -> room arrival -> tap resident or real station -> path to authored approach -> contextual interaction -> camera closeup -> action, visible response, result -> optionally save/retry -> same safe station in room -> exit to original outdoor doorway. Explicit railway selection or Map destination -> full-screen ride -> automatic arrival. No confirmation page, permanent Next Stop CTA or required visits. An optional recommendation never travels automatically. No invisible timer triggers a game before actual arrival.

## Interaction grammar
One tap on walkable terrain walks. One tap on a physical prop or resident walks into reach and opens its relevant interaction after arrival; no redundant Start click unless a meaningful choice is needed. A second movement command cancels pending approach; tap another station reroutes; never double-dispatch. Tap decorative scenery does nothing. Gentle contact highlight only on proximity/focus, not persistent bouncing icons or arrows. Labels attached to wood/stone/printed paper if needed; otherwise a small contextual label outside the object silhouette. Use shared collision/perspective coordinates and actual contact surfaces, not a separate render clamp. Controls and furniture must match. Every action has visual feedback, optional sound, and accessible input. No touch gesture triggers browser scrolling inside a focused playing surface; allow scrolling on actual forms. Never require hover. Show controls only when actionable, disable during a committed animation, and re-enable predictably. Never charge twice; never grant repeated rewards due to double tap.

## Layout by state (proposed; tune against actual screenshots)
Outdoor: top-left compact profile/name/level, top-right wallet/settings, small centered location title in its own safe band. No lunar permanent banner. Bottom five destinations Bag, Passport, Home, Map, Today. Home denotes personal home; use Exit/Back for returning outdoors. Joystick bottom-left above dock, only when moving is relevant; direct taps also work. Safe areas respected. Railway lives at far end of physical path, not bottom-right. Map local shop list first, onward rail choices second. Indoor: top-left Outside or Exit; room name elsewhere in header; hide dock and redundant profile/wallet unless needed for buying. Keep joystick only during room exploration. Activity: top-left contextual Back to table/courtyard/machine; single action area near physical prop or bottom center, no global dock, joystick, or unrelated stats. Results: keep scene and use an object such as journal, card, note or receipt; save/retry/return actions adjacent below result. Train: immersive viewport, no HUD or ticket overlay; brief Next stop caption outside window focal area, automatic arrival; reduced motion. Journal/shop: real scrollable layout, consistent close/back at top, sticky action only for pending purchase, no labels covered. At 320–430 CSS px use 44px minimum touch targets and safe area insets, short labels and one/two columns only when readable; desktop displays wider scenery with same relative anchors, keyboard and mouse controls, not enlarged UI. No horizontal scroll.

## Entrance and railway
Ticket is a keepsake. Station counter opens ticket form, name and full-body avatar selection; use 2x2 on phone, four across if wide. Selecting avatar highlights it without immediately departing; one Board train confirms identity; restore prior selections on Back. Language can change without resetting entered name. Moving window outside stable carriage, original entrance art shared, separately painted route-specific far/near scenery layers. Mountains/cherry blossoms to Fortune; river/rice fields to Lazy; coast/boats to Munch; twilight hills/lanterns to discovery district. No cropped maps, flat vector panorama or new ticket form during ordinary transfer. Train ride auto completes; shorter static/reduced motion option; avoid repeated intro for returning players. Physical station tap intentionally boards next route, Map selected destination boards direct; separate stay/preview only for optional suggestion. Keep existing maps and verify real names against source.

## District and house click paths
### Fortune Valley
- NPCs only along traced painted staircase, no Mount Fuji skyline/roof/trees; direction follows slope, foot contact, distance scale, foreground occlusion. Door plaques attached to actual buildings; no extra permanent arrows.
- Temple water: tap stone basin -> approach visitor side -> take ladle -> tilt/pour water over hands -> place ladle back -> local reaction -> Back to courtyard. Bell: tap suspended bell/striker -> approach correct side -> pull/swing -> contact and recoil -> resonance -> restore striker. Prayer: tap incense tray/altar -> collect three -> light -> bow three times -> insert into burner -> smoke/reaction -> done. Optional, no gating. Fortune sticks: tap cup -> hold and shake -> one stick falls onto tray -> pick up -> read matched paper -> keep/tie if supported -> return. Moon blocks: pick question quietly -> take two blocks -> toss -> settle visibly with matching result -> read -> retry/return. Keep the hidden garden reachable as a path. No floating props.
- Tarot: tap reading table -> walk to chair -> resident offers Daily or question reading -> topic cards on actual cloth, title inside each card, no separate overlapping caption; choose topic -> existing prompt/tone choices; no forced typed private question -> shuffle physical deck -> Deal -> individually flip -> optional closeup -> return spread -> read/save or back to table. Different stage bounds for 1,3,5-card layouts, retain existing supported spread and reward semantics. No text drawn under cards. Do not auto flip or auto return.
- Master Yue: approach consultation desk -> choose self/other -> local birth date, optional time and place, clear unknown-time branch -> calculate -> chart with readable sections -> choose interpretation area/followup -> back to chart -> desk. No huge host covering form; no invented chart precision. Do not transmit private details.
- Wishing Garden: walk to actual pond edge or plaque rack. Coin rests on tray, not floating. Flick from edge toward bowl -> trajectory/landing/ripple/fish reaction -> retry/keep. Optional keyboard aim controls collapsed. Wish plaque: choose blank wood -> private text or quiet wish -> tie to physical rack -> reaction -> return. Preserve game geometry, no leaking private wishes. Pond art and interactive bowl/tray/koi must be independent or exactly aligned, not a standalone flat rectangle.

### Lazy Island
- Ah Ma stall: walk to paper prep stool/table -> resident greets -> optional symbolic name/private worry -> paper laid on brick -> pick up slipper -> strike with wrist/body contact and paper deformation -> her reaction -> finish/try again. Never target a real person or Ah Ma. Tools reset on exit.
- Writing bench: write privately (or skip text) -> fold -> seal imaginary bottle -> approach bank -> aim/flick -> float/splash/dissolve -> response -> return. Shout: reach lookout -> type or choose playful preset -> press release -> visible pose/echo/reeds/birds -> reaction. No microphone. These are connected areas of one pier, not separate app menus.
- Tea room: approach chair -> sit -> choose gossip/celebrate/check in -> dialogue bottom safe band with portrait and short lines -> choose response -> return to same table; no forced auto conversation. Noticeboard physically wall-mounted, tap to read, open thread, back to same scroll, compose only if real sharing configured; fictional posts distinctly labeled. Preserve ongoing serials/relationships.
- Park: tap animal -> walk within reach, stop if animal moves -> bow for deer, wait for reaction -> feed/pet only when appropriate -> trust reaction -> continue. Feet and animals depth-sort; no animal covering avatar/hit controls. Bench is scenery/social context, not a duplicate game. Office comedy remains curated in Tea Room if current implementation has moved it; no duplicate door.

### Munch & Play
- Grandma kitchen: approach counter -> choose recipe from physical book -> ingredients on shelves/trays -> drag/tap ingredient to chopping board/bowl -> visible prep -> stove/pot -> stir and cook -> plate -> serve/taste -> Grandma reaction -> recipe memory; next input only when step ready. No disconnected ingredient buttons on blank page. Preserve current recipes.
- Boba: approach counter -> order slip -> cup dispenser -> base -> pearls/toppings -> sugar/ice -> mix -> seal -> serve -> reaction. Controls on containers or lower accessible action rail; cup stays supported/held, liquids move into cup. Do not auto-add ingredients not chosen.
- Arcade: cabinets physically stand on floor, central aisle. Tap cabinet -> approach -> zoom into cabinet screen; controls at machine console or accessible bottom strip; no flying icons. Claw: move left/right -> drop once -> grasp/release -> collect in chute -> result. Bubble game: aim and shoot on cabinet screen -> settle/score -> replay/exit. Goldfish: approach tank -> select net -> scoop gently -> paper durability and water reaction -> return fish -> result. Blind box: shelf -> select box -> review price/confirm only if cost -> counter -> unwrap/shake -> reveal -> inventory -> shelf, preserve rarity/rewards. Keep active game list, no redundant old activities.
- Furniture showroom: actual display/physical catalogue -> category -> preview item in home context -> price and owned state -> confirm purchase -> choose placement -> return to same catalogue position. No spending on preview; clear insufficient balance and purchased state.

### Discovery district / Wonder Valley (verify current public display name)
- Personality Lab: approach bookshelf/consultation desk -> choose assessment book -> answer one question at a time -> progress and Back within assessment -> result journal -> save/retake/return. Include Enneagram only with honest validated scoring, no deterministic claims; distinguish Soul Cat, preference and motives. No auto advancement before answer feedback; no meaningless duplicate tests.
- Parallel Lives: approach storybook -> choose premise -> animated scene -> meaningful choice -> scene consequence -> branch -> distinct ending -> keep chapter memory -> replay other branch or return. No same picture for every scene, no result questionnaire masquerading as story. Preserve existing endings.
- Compatibility Café: approach table -> choose relationship context -> conversational prompts -> reflect on differences -> response -> keep private notes if chosen or return. Distinct from astrology/personality tests. No claims of scientific relationship prediction.

## Home and collections
Home dock opens personal room directly. Enter from doorway, basic bedding, place furniture from owned inventory; edit mode shows placement ghost only during edit, confirm/cancel, rotate if valid, no hidden overlap. Finish returns to same home view, not town. Expand via physical door or explicit extension purchase, preserve furniture. Bag has category/filter and illustrated item detail, Back returns same scroll; passport has original ticket, stamps and memories; profile has full body avatar, visible level and life attributes, edit identity without losing balance or progress. Today contains optional recommendations, short humor, no compulsory streak. Settings uses one compact entry; language selection collapses, does not reset current state. Leave unfinished action only when needed; meaningful purchases/private inputs warrant clear confirmation, normal walks and rides do not.
